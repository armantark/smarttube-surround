## 3. Update mechanism

- `AppUpdatePresenter` loads `R.array.update_urls` and passes the URLs to `AppUpdateChecker`; the beta and stable flavors define those arrays in separate resources, so a fork can patch the endpoint without changing updater Java code. Beta points to `https://github.com/yuliskov/SmartTubeNext/releases/download/latest/smarttube_beta2.json`; stable points to `https://github.com/yuliskov/SmartTubeNext/releases/download/latest/smarttube_stable2.json`. Sources: [`AppUpdatePresenter.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/app/presenters/dialogs/AppUpdatePresenter.java), [beta URL resource](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/stbeta/res/values/update_urls.xml), [stable URL resource](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/ststable/res/values/update_urls.xml).
- The JSON schema has a top-level `package` object containing `downloadUrl`, `downloadUrlList`, or ABI-specific `downloadUrlList_<ABI>` URLs; each version-name key maps to integer `versionCode` and optional localized changelog arrays. `AppVersionChecker` compares the installed package version code to the highest listed code. At retrieval, both live manifests had top entry `32.56` / code `2446`; the beta manifest lists beta APKs and stable lists stable APKs. Sources: [`AppVersionChecker.java`](https://github.com/yuliskov/SharedModules/blob/d4f09b11133036d90826baf012e120d06486ae73/appupdatechecker2/src/main/java/com/liskovsoft/appupdatechecker2/core/AppVersionChecker.java), [live beta manifest](https://github.com/yuliskov/SmartTubeNext/releases/download/latest/smarttube_beta2.json), [live stable manifest](https://github.com/yuliskov/SmartTubeNext/releases/download/latest/smarttube_stable2.json).
- `AppUpdateChecker` requires a downloaded APK of at least 1,000,000 bytes and caches a check for 15 minutes. Its archive validation reads `PackageInfo` and compares only `packageName` to the running app; no APK certificate/signature verification appears in this updater path. Sources: [`AppUpdateChecker.java`](https://github.com/yuliskov/SharedModules/blob/d4f09b11133036d90826baf012e120d06486ae73/appupdatechecker2/src/main/java/com/liskovsoft/appupdatechecker2/AppUpdateChecker.java), [updater manifest](https://github.com/yuliskov/SharedModules/blob/d4f09b11133036d90826baf012e120d06486ae73/appupdatechecker2/src/main/AndroidManifest.xml).
- The app presents an explicit “Install update” action. The updater delegates installation to `Helpers.installPackage`, which creates a FileProvider URI and starts `Intent.ACTION_VIEW` with MIME `application/vnd.android.package-archive`, `FLAG_ACTIVITY_NEW_TASK`, and `FLAG_GRANT_READ_URI_PERMISSION`; the updater manifest declares `REQUEST_INSTALL_PACKAGES`. Android then enforces signer compatibility: an APK update for the same package must use a matching signing certificate, while a different certificate requires a different package name and installs as a separate app. Sources: [`AppUpdatePresenter.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/app/presenters/dialogs/AppUpdatePresenter.java), [`Helpers.java`](https://github.com/yuliskov/SharedModules/blob/d4f09b11133036d90826baf012e120d06486ae73/sharedutils/src/main/java/com/liskovsoft/sharedutils/helpers/Helpers.java), [Android app-signing guidance](https://developer.android.com/studio/publish/app-signing).

## 4. Audio pipeline

- SmartTube vendors Amazon’s ExoPlayer port at `exoplayer-amzn-2.10.6`; its library version is `2.10.6`. The app depends on in-tree ExoPlayer core/UI and Leanback/MediaSession extensions, not AndroidX Media3. Sources: [vendored port README](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/exoplayer-amzn-2.10.6/README.md), [`ExoPlayerLibraryInfo.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/exoplayer-amzn-2.10.6/library/core/src/main/java/com/google/android/exoplayer2/ExoPlayerLibraryInfo.java), [`smarttubetv/build.gradle`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/smarttubetv/build.gradle).
- `ExoPlayerInitializer.createPlayer` calls `ExoPlayerFactory.newSimpleInstance(context, renderersFactory, trackSelector, loadControl)`. `CustomOverridesRenderersFactory` normally delegates renderer creation to ExoPlayer; when audio delay or the sync fix is enabled, it replaces the audio renderer and supplies `DefaultAudioSink(AudioCapabilities.getCapabilities(context), audioProcessors)`. The vendored `AudioCapabilities` reads `ACTION_HDMI_AUDIO_PLUG` and advertised encodings/channel count, with Amazon-specific surround settings; absent an advertised route it defaults to PCM 16-bit. Sources: [`ExoPlayerInitializer.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/exoplayer/other/ExoPlayerInitializer.java), [`CustomOverridesRenderersFactory.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/exoplayer/versions/renderer/CustomOverridesRenderersFactory.java), [vendored `AudioCapabilities.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/exoplayer-amzn-2.10.6/library/core/src/main/java/com/google/android/exoplayer2/audio/AudioCapabilities.java).
- Existing settings include a tunneled-playback boolean whose stored default is false, and audio delay in milliseconds plus a separate enable switch whose defaults are 0 ms/false; audio-sync fix is also stored separately. No user-facing passthrough toggle was found in the inspected settings source: passthrough support is supplied through `AudioCapabilities`. Sources: [`PlayerTweaksData.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/prefs/PlayerTweaksData.java), [`PlayerData.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/prefs/PlayerData.java), [`CustomOverridesRenderersFactory.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/exoplayer/versions/renderer/CustomOverridesRenderersFactory.java).
- Audio presets encode the codec filter: `mp4a`, `ec-3`, and `ac-3`. The default is AC-3 when the device reports VP9 support at 2160p, otherwise MP4A/AAC; comments in that method mention Opus but the code does not choose an Opus preset. The selected format is matched against stream format fields, including codec, language, bitrate, and DRC; no separate always-prefer-Opus-over-AAC rule was found. Sources: [`FormatItem.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/exoplayer/selector/FormatItem.java), [`PlayerData.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/prefs/PlayerData.java), [`TrackSelectorManager.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/exoplayer/selector/TrackSelectorManager.java), [`ExoFormatItem.java`](https://github.com/yuliskov/SmartTube/blob/f62f8de081bef45a03d8a8c922f02a51b40c0c72/common/src/main/java/com/liskovsoft/smartyoutubetv2/common/exoplayer/selector/ExoFormatItem.java).

## 5. Prior art and Android audio APIs

- A GitHub issue search for “upmix” returned no SmartTube issue results. Surround-related reports do exist: issue [#6335](https://github.com/yuliskov/SmartTube/issues/6335) asks for a missing 5.1 option (opened 2026-10-17); [#6258](https://github.com/yuliskov/SmartTube/issues/6258) reports missing AC-3/E-AC-3 5.1 options; [#4661](https://github.com/yuliskov/SmartTube/issues/4661) reports 5.1 playback falling back after leaving settings; and [#2193](https://github.com/yuliskov/SmartTube/issues/2193) describes a codec-quality/5.1 selection tradeoff. These reports concern selecting or playing existing surround streams, not stereo upmixing.
- ExoPlayer’s `AudioProcessor` contract accepts `@C.PcmEncoding` input and reports PCM output encoding; `DefaultAudioSink` documents its processors as processing PCM before output. Its `ChannelMappingAudioProcessor` explicitly supports reordering, duplicating, or discarding PCM channels and handles PCM 16-bit; channel duplication is available as a primitive, but it cannot synthesize silent or independent center/LFE channels or encode AC-3/AAC. No official ExoPlayer 2.10.6 example was found that re-encodes processed PCM for HDMI passthrough; that requires an encoder plus a renderer/sink route beyond the standard PCM processor chain. Sources: [ExoPlayer `AudioProcessor`](https://github.com/google/ExoPlayer/blob/r2.10.6/library/core/src/main/java/com/google/android/exoplayer2/audio/AudioProcessor.java), [ExoPlayer `DefaultAudioSink`](https://github.com/google/ExoPlayer/blob/r2.10.6/library/core/src/main/java/com/google/android/exoplayer2/audio/DefaultAudioSink.java), [ExoPlayer `ChannelMappingAudioProcessor`](https://github.com/google/ExoPlayer/blob/r2.10.6/library/core/src/main/java/com/google/android/exoplayer2/audio/ChannelMappingAudioProcessor.java).
- Android defines `ENCODING_AC3` from API 21 and `ENCODING_AAC_LC` from API 28. An `AudioTrack` with a compressed encoding requests a direct, non-mixed track to an endpoint capable of decoding it; other endpoints generally need the stream decoded first. `AudioTrack.isDirectPlaybackSupported(format, attributes)` arrived in API 29 and was deprecated in API 33 in favor of `AudioManager.getDirectPlaybackSupport(format, attributes)`, which arrived in API 33. The support query is format- and attributes-dependent and does not promise that playback resources are available at that moment; Android says the framework may wrap the stream in a higher-level protocol such as IEC61937 for passthrough. Sources: [Android `AudioFormat`](https://developer.android.com/reference/android/media/AudioFormat), [Android `AudioTrack`](https://developer.android.com/reference/android/media/AudioTrack), [Android `AudioManager`](https://developer.android.com/reference/android/media/AudioManager).
- The direct-playback query requires an `AudioAttributes` value. Android identifies `USAGE_MEDIA` as the usage for music or movie soundtracks and recommends supplying usage; `CONTENT_TYPE_MOVIE` may be supplied when known. The API reference describes compressed data as bytes/access units and says direct compressed writes need not be exact multiples of an access unit, but it does not specify whether AAC-LC `AudioTrack` input should be ADTS-framed or raw. Sources: [Android `AudioAttributes`](https://developer.android.com/reference/android/media/AudioAttributes), [Android `AudioFormat`](https://developer.android.com/reference/android/media/AudioFormat).

## Open questions requiring a build or device test

- Build the beta and stable release variants against the documented JDK options: SmartTube's README says OpenJDK 14 or older, while upstream CI uses JDK 17. Confirm which works with the checked-in Gradle/AGP and SDK/NDK setup; no build was run for this research.
- On the target TV/Android version, confirm `MediaCodec` exposes an AAC-LC encoder that can produce six-channel output (or an AC-3 encoder if that route is selected), and verify `AudioManager.getDirectPlaybackSupport` for the exact output format plus media `AudioAttributes`.
- On the actual HDMI/eARC chain, verify the output reaches the soundbar as discrete 5.1, including channel order and the encoder's AAC framing; the Android API reference did not settle ADTS versus raw AAC input to `AudioTrack`.
